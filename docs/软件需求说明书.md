# 《智巢中枢（SmartNest）——智能家居规则编排与交互仿真系统》软件需求说明书

## 1. 引言

### 1.1 项目背景与目标
针对物联网家居场景中设备种类多、状态联动复杂、规则配置不直观等痛点，本项目基于 HarmonyOS 5.0.5 (API 17) 与 ArkTS/ArkUI 框架，设计并实现一款具有**设备状态实时监控、交互控制、可视化规则编排、环境物理反馈仿真及本地数据持久化**能力的智能家居中控应用——**智巢中枢（SmartNest）**。

本系统不依赖真实硬件网关，通过面向对象建模与环境仿真引擎模拟多房间传感数值变化与设备物理反馈，并运行真实的 `IF-THEN` 多条件规则引擎驱动设备自动联动与异常保护。

### 1.2 基本信息
- **选题方向**：主题三：智能场景规则编排与交互仿真系统
- **开发模式**：独立完成（个人全栈设计、编码、测试与集成）
- **GitHub 账号**：`SongRan-mk`
- **GitHub 仓库**：`https://github.com/SongRan-mk/smart-nest-harmony`
- **运行环境**：HarmonyOS 5.0.5 (API 17)，DevEco Studio，ArkTS + ArkUI + Ability Kit + ArkData

## 2. 功能需求与模块划分

系统按职责划分为以下六大核心功能模块：

### 2.1 多房间设备看板与交互控制模块
- 支持按房间（全部、客厅、卧室、书房、阳台）筛选展示智能设备。
- 区分**传感器设备**（温度、湿度、光照、人体红外、烟雾浓度）与**执行器设备**（空调、智能主灯/台灯、电动窗帘、空气净化器、智能门锁、声光报警器）。
- 支持执行器一键开关、详情页精细调参（目标温度 16~30℃、亮度 0~100%、窗帘开合度 0~100%、门锁锁定/解锁）及模拟设备“离线/在线”故障切换。
- 支持一键切换全局**场景模式**（回家模式、睡眠模式、离家布防、应急复位），批量联动相关设备。

### 2.2 可视化规则编排器模块
- 支持用户查看、启用/停用、新建、编辑、删除自动化联动规则。
- 每条规则支持配置：
  - 规则名称与逻辑组合方式（`AND` 全部满足 / `OR` 任一满足）；
  - 1~N 条触发条件（目标传感器 + 比较运算符 `>` / `>=` / `<` / `<=` / `==` / `!=` + 阈值）；
  - 1~N 条联动动作（目标执行器 + 目标开关状态 + 可选调节档位/温度）；
  - 冷却防抖时间（防止相邻周期重复触发造成日志刷屏或设备抖动）。
- 提供规则合法性校验（空名称、空条件、空动作、非法 `NaN` 阈值或超限阈值拦截）。

### 2.3 规则求值与执行引擎模块（`RuleEngine`）
- 每次环境采样推进、传感器手动微调或用户点击“立即评估”时，按**规则优先级（紧急 > 高优 > 常规 > 节能）降序**执行全量启用规则扫描。
- 真实解析每条规则的条件列表与 `AND/OR` 组合逻辑，返回命中详情、跳过原因（如未启用、冷却中、设备离线、非法阈值）与动作执行结果。
- 内置**同周期执行器冲突仲裁机制**：高优先级规则操作执行器后会在当前周期内锁定该设备，防止低优先级规则互相覆盖（如高温遮阳与烟雾应急通风并发时，强制保留烟雾应急全开窗帘），并输出可追踪的冲突仲裁日志。
- 动作执行阶段对不存在设备或离线设备做异常拦截并输出可追踪日志。

### 2.4 环境交互仿真与趋势可视化模块（`SimulationEngine`）
- 支持手动拖动传感器滑块即时改变环境参数（如模拟室温升高、光照变暗、烟雾浓度骤增），并立刻触发规则引擎响应。
- 支持开启/暂停**自动周期仿真**：按时间步长模拟室内温湿度、光照自然波动，并结合当前已开启执行器的状态产生**真实物理反馈**（如空调开启制冷时室温逐步向目标温度回落、窗帘拉开提升室内光照、空气净化器运行时改善环境）；并响应 `UIAbility` 前后台生命周期，退至后台自动挂起定时器并在回到前台后恢复。
- 提供突发工况演练快捷入口（模拟高温热浪、烟雾告警、夜晚降临）、**24h 智巢一天 5 幕沉浸式互动剧场（配智巢管家实时解说气泡）**及全屋顶部紧急告警应急条。
- 使用 ArkUI `Canvas` 绘制环境指标历史折线趋势图（支持温度、湿度、光照、烟雾、总功耗切换查看），并实时统计全屋总功率（W）、估算日耗电量（kWh）与电费及动态节能建议。

### 2.5 数据持久化与状态恢复模块（`PersistenceService`）
- 在 `EntryAbility` 启动时接入 `UIAbilityContext`，初始化 `@kit.ArkData` `preferences` 实例。
- 自动保存设备运行状态（开关、数值、在线状态）、用户自定义及修改后的规则列表、当前激活场景、仿真配置与最近联动执行日志。
- 应用关闭并重新启动后自动反序列化恢复全部核心业务数据；若本地存储缺失或 JSON 格式损坏，安全回退至出厂默认配置并记录异常恢复信息。

### 2.6 联动日志与 Mock 自检验证模块
- 按日志类别（全部、规则联动、手动控制、场景切换、异常拦截）时间倒序展示全部可追溯事件。
- 内置一键 Mock 自检面板与独立 Hypium 单元测试套件，覆盖**正常、边界、异常**三类测试场景。

## 3. 系统整体架构

系统采用清晰的四层分层架构，确保业务逻辑与 UI 渲染解耦，便于单元测试与维护：

```text
+-----------------------------------------------------------------------+
|                       表现层 (UI Presentation Layer)                   |
|  pages/Index (Tabs + NavPathStack)                                    |
|   ├── components/HomeFloorPlan (全屋数字孪生交互沙盘)                  |
|   ├── components/DeviceCard    (可复用设备状态与开关卡片)              |
|   ├── components/EnvironmentChart (Canvas 历史趋势折线图)              |
|   ├── view/DashboardView     (多房间看板、场景芯片、突发演练)          |
|   ├── view/RulesView         (规则列表、开关控制、单条试运行)          |
|   ├── view/SimulationView    (Canvas 趋势图、能耗统计、内置 Mock 自检) |
|   ├── view/LogsView          (分类联动日志、数据重置)                  |
|   ├── pages/DeviceDetailPage (传感器滑块仿真、执行器精细调参、离线模拟) |
|   └── pages/RuleEditorPage   (可视化规则新建与编辑)                    |
+-----------------------------------------------------------------------+
                                    | 状态订阅 / 方法调用
                                    v
+-----------------------------------------------------------------------+
|                     状态协调层 (State Orchestration)                   |
|  service/SmartHomeStore                                               |
|   └── 统一协调设备集合、规则列表、仿真定时器、日志写入与异步持久化     |
+-----------------------------------------------------------------------+
          |                         |                         |
          v                         v                         v
+-------------------+   +-----------------------+   +-------------------+
| 核心规则引擎层     |   | 环境物理仿真引擎层     |   | 数据持久化层       |
| service/RuleEngine|   | service/Simulation    |   | service/          |
| - 条件求值        |   |   Engine              |   |  PersistenceService|
| - AND/OR 聚合     |   | - 环境步进与反馈      |   | - ArkData         |
| - 冷却防抖与执行  |   | - 实时功耗与采样队列  |   |   preferences     |
+-------------------+   +-----------------------+   +-------------------+
          \                         |                         /
           \                        v                        /
            +-----------------------------------------------+
            |        领域模型层 (Domain Model Layer)         |
            |  model/Types, model/DeviceModels,             |
            |  model/DefaultDataFactory                     |
            |  - BaseDevice -> SensorDevice / ActuatorDevice|
            |  - AutomationRule, ScenePreset, ExecutionLog  |
            +-----------------------------------------------+
                                    ^
                                    | Ability Kit 上下文注入
                        entryability/EntryAbility
```

### 数据流向说明
1. **启动恢复流**：`EntryAbility.onCreate()` 初始化上下文 → `SmartHomeStore.init(context)` 调用 `PersistenceService.loadSnapshot()` 读取持久化数据 → 还原设备对象树与规则集合 → 驱动 ArkUI 首页渲染。
2. **规则联动流**：用户调节传感器滑块或 `SimulationEngine` 定时步进 → 更新 `SensorDevice` 数值并采集 `EnvironmentSnapshot` → 触发 `RuleEngine.runCycle()` 求值全部启用规则 → 命中规则后修改 `ActuatorDevice` 状态 → 写入 `ExecutionLog` → 调用 `PersistenceService.saveSnapshot()` 落盘并通知 UI 刷新。

## 5. 核心数据结构设计

### 5.1 设备面向对象类层次
- **`BaseDevice`（抽象基类）**
  - `id: string`：设备唯一标识
  - `name: string`：设备名称
  - `roomId: RoomId`：所属房间（`living_room` / `bedroom` / `study` / `balcony`）
  - `category: DeviceCategory`：设备大类（`sensor` / `actuator`）
  - `kind: DeviceKind`：设备细分类型
  - `online: boolean`：在线状态（支持故障离线模拟）
  - `ratedWatts: number`：额定功率（W）
  - `lastUpdated: number`：最近状态更新时间戳
  - 抽象/多态方法：`getSummaryText(): string`、`getEffectiveWatts(): number`、`toSerialized(): SerializedDeviceState`
- **`SensorDevice extends BaseDevice`（传感器子类）**
  - `metricKey: MetricKey`：监测指标键名（`temperature` / `humidity` / `illuminance` / `smokeLevel` / `motionDetected`）
  - `value: number`：当前测量数值
  - `unit: string`：单位（`℃` / `%` / `lux` / `ppm` / `态`）
  - `minVal: number`、`maxVal: number`：合法量程上下界
  - 方法：`updateReading(newValue: number): boolean`（拦截 `NaN` 并做量程边界钳制）
- **`ActuatorDevice extends BaseDevice`（执行器子类）**
  - `powerOn: boolean`：电源开关状态
  - `levelValue: number`：当前设定数值（如温度 24℃、亮度 80%、开合度 60%）
  - `minLevel: number`、`maxLevel: number`、`unit: string`
  - `modeText: string`：运行模式描述（如“制冷”“柔光”“警戒”）
  - 方法：`setPower(on: boolean): void`、`setLevel(val: number): boolean`、`getEffectiveWatts(): number`

### 5.2 规则、场景与日志结构
- **`RuleCondition`**：`id`, `deviceId`, `metricKey`, `operator` (`gt`/`gte`/`lt`/`lte`/`eq`/`neq`), `threshold: number`
- **`RuleAction`**：`id`, `deviceId`, `targetPowerOn: boolean`, `targetLevel?: number`, `targetMode?: string`
- **`AutomationRule`**：`id`, `name`, `enabled: boolean`, `logic: 'AND' | 'OR'`, `conditions: RuleCondition[]`, `actions: RuleAction[]`, `cooldownMs: number`, `lastTriggeredAt: number`, `triggerCount: number`
- **`ScenePreset`**：`id`, `name`, `description`, `accentColor`, `actions: RuleAction[]`
- **`ExecutionLog`**：`id`, `timestamp`, `source` (`rule`/`manual`/`scene`/`error`), `title`, `detail`, `ruleId?: string`
- **`EnvironmentSnapshot`**：`timeLabel`, `temperature`, `humidity`, `illuminance`, `smokeLevel`, `totalWatts`

## 6. 核心模块接口定义

### 6.1 `RuleEngine` 接口
| 方法签名 | 输入参数 | 返回值 | 边界与异常处理 |
| :--- | :--- | :--- | :--- |
| `evaluateCondition(cond, devices)` | 条件对象、设备列表 | `ConditionEvalResult` | 设备缺失或离线返回 `matched: false` 并附原因；`threshold` 为 `NaN` 拦截报错 |
| `evaluateRule(rule, devices, nowMs)` | 规则对象、设备列表、当前时间戳 | `RuleEvalResult` | 规则未启用、空条件列表、冷却期未满（`nowMs - lastTriggeredAt < cooldownMs`）均不触发 |
| `executeActions(rule, devices)` | 规则对象、设备列表 | `ActionExecResult[]` | 目标执行器缺失或离线时跳过该动作并标记 `success: false` 与失败原因 |
| `runCycle(rules, devices, nowMs)` | 规则数组、设备数组、时间戳 | `EngineCycleSummary` | 对所有启用规则按顺序求值并汇总触发数量、执行动作数与异常告警 |

### 6.2 `SimulationEngine` 接口
| 方法签名 | 输入参数 | 返回值 | 边界与异常处理 |
| :--- | :--- | :--- | :--- |
| `stepEnvironment(devices, tickIndex)` | 设备列表、仿真步序号 | `SimStepResult` | 仅对在线传感器更新；温度/湿度/光照/烟雾严格限制在物理量程内 |
| `captureSnapshot(devices, label)` | 设备列表、时间标签 | `EnvironmentSnapshot` | 传感器缺失时回退安全默认值，避免除零或 `NaN` |
| `calculateTotalWatts(devices)` | 设备列表 | `number` | 离线或关闭的执行器按 `0W` 计入，不计负数功耗 |

### 6.3 `PersistenceService` 接口
| 方法签名 | 输入参数 | 返回值 | 边界与异常处理 |
| :--- | :--- | :--- | :--- |
| `init(context: Context)` | `UIAbilityContext` | `Promise<void>` | 重复调用幂等保护；首选项打开失败时捕获并标记内存降级模式 |
| `saveSnapshot(snapshot)` | 序列化状态对象 | `Promise<boolean>` | 序列化或 `flush` 异常时捕获错误并返回 `false`，不中断主流程 |
| `loadSnapshot()` | 无 | `Promise<PersistedAppState \| null>` | 本地无数据返回 `null`；JSON 损坏时捕获 `SyntaxError` 返回 `null` 触发默认恢复 |
| `clearAll()` | 无 | `Promise<void>` | 清空全部持久化键值以便“恢复出厂设置” |

## 7. 数据存储与持久化方式

1. **存储方案**：采用 HarmonyOS 官方轻量级键值持久化组件 `@kit.ArkData` 的 `preferences`（首选项名称：`smart_nest_store`）。
2. **存储键值规划**：
   - `devices_state_v1`：序列化后的所有设备在线状态、传感器读数、执行器开关与档位；
   - `rules_list_v1`：全部自动化联动规则列表（含启用状态、触发次数、最近触发时间）；
   - `logs_list_v1`：最近 80 条系统运行与联动日志；
   - `sim_config_v1`：自动仿真开关、当前仿真步数、历史采样快照队列（最多 24 点）；
   - `active_scene_v1`：当前激活的场景模式 ID。
3. **重启恢复与容错机制**：
   - 应用冷启动时 `EntryAbility` 注入 `context` 完成首选项加载；
   - 将持久化中的状态映射回 `SensorDevice` / `ActuatorDevice` 类实例（保留面向对象行为方法），同时将新增的默认设备与已存状态安全合并；
   - 当本地记录被清空或格式异常时，自动重建出厂默认房间、设备与规则，确保应用在任何情况下都能稳定启动运行。
